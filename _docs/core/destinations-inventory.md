## Which ad points where: readable through the Graph API, not the MCP

The facebook-ads MCP tools do not expose an ad's destination at any level (ad, creative, ad set, preview); a read-only scan of all 587 active Basmo IOS ads on 2026-09-15 confirmed it (`link_url` blank on every creative, `object_story_spec` not projected).

What does work (found 2026-09-15): the read-only script `scripts/ad-destinations.ts` in `~/Hub/focus/project - auto-ads-four/` (node, token in that project's `.env.local`) reads every destination the Graph API exposes per ad: store URL, custom product page id, deep link, url_tags. First run on ad set 120246661279120160 (CPT US iOS, 16 ads): all point at the App Store page id6448849666 with custom product page `74c0e8e2-5028-4964-817a-c315959f115e` = **Parenting V1**, no deep links. Output: `_projects/funnel-maps/data/readings/app/adset-120246661279120160_destinations.json`. Running it over all active ads (`--days` or `--since`, `--json`) gives the full ad-to-page pairing; not done yet.

Fallback: Ads Manager, ad level, export with the App Store URL column (carries the ppid).

What the scan did give: 534 active app-install ads across 35 campaigns, $131.7k spend and 44.4M impressions in the 7 days to 2026-09-15; the 53 web-style ads (CTA Learn more) in the account were all dormant, zero spend. Top campaign: "Biblechat CPT - LATAM - IOS - June 05, 2026 - Cristina" at $14.7k. Raw rows: `_projects/funnel-maps/data/meta-active-ads-2026-09-15.json`.
